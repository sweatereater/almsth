# Сабагенты Codex в Almsth

## Что настроено

В проекте определены три специализированных профиля:

- `almsth_architect` — только читает проект и составляет карту изменений и рисков;
- `almsth_developer` — реализует одну согласованную задачу и добавляет проверки;
- `almsth_qa` — независимо проверяет поведение и запускает тесты, но не меняет исходники.

Главный агент отдельного профиля не требует: это текущая задача Codex. Он принимает решения,
запускает сабагентов, объединяет их выводы и отвечает пользователю.

Балансировщика пока нет. Его можно добавить позднее, когда появится достаточно полный игровой
цикл и реальные данные для сравнения решений.

## Как это работает

Файлы в `.codex/agents/` не являются постоянно запущенными процессами. Они описывают роли,
которые главный Codex создаёт только тогда, когда задача этого требует. У каждого сабагента
своя ветка разговора и контекст, но агенты работают с тем же проектом.

Стандартный цикл выглядит так:

1. архитектор находит затрагиваемые системы;
2. QA формулирует критерии приёмки и риски;
3. главный агент объединяет результаты в одну спецификацию;
4. один разработчик меняет код и тесты;
5. QA независимо проверяет готовое изменение;
6. разработчик исправляет только подтверждённые дефекты;
7. главный агент подводит итог.

Архитектор и QA могут работать параллельно. Разработчик работает после них и остаётся
единственным агентом, меняющим исходники этой функции.

## Как попросить использовать команду

Для большой функции достаточно написать:

```text
Реализуй <описание функции> по стандартному процессу сабагентов проекта Almsth.
Сначала дождись выводов архитектора и QA, затем передай согласованную реализацию одному
разработчику и после изменений проведи независимую QA-проверку.
```

Для анализа без изменений:

```text
Попроси almsth_architect исследовать <область>, а almsth_qa составить тестовую матрицу.
Дождись обоих и верни объединённый отчёт. Ничего не меняй.
```

Для независимой проверки готовой работы:

```text
Передай текущие изменения almsth_qa. Пусть он проверит реальные изменения, запустит
подходящие тесты и сообщит только подтверждённые проблемы с шагами воспроизведения.
```

Для маленькой правки или когда сабагенты не нужны:

```text
Исправь это напрямую, без сабагентов. Изменение локальное: <описание>.
```

Активность сабагентов отображается в интерфейсе Codex. Главный агент дожидается их результатов
и получает краткие отчёты вместо полного потока команд и логов.

## Где лежит конфигурация

- `.codex/config.toml` — включает сабагентов и ограничивает параллельность;
- `.codex/agents/almsth-architect.toml` — профиль архитектора;
- `.codex/agents/almsth-developer.toml` — профиль разработчика;
- `.codex/agents/almsth-qa.toml` — профиль QA;
- `AGENTS.md` — обязательный порядок совместной работы для этого репозитория.

Профили намеренно не закрепляют конкретную модель: они наследуют модель главной задачи и не
ломаются, если доступный набор моделей изменится. Параллельные сабагенты расходуют больше
токенов, поэтому процесс применяется к существенным задачам, а не к каждой мелкой правке.
