# Технический аудит Almsth

Дата аудита: 28 августа 2026 года.

## Итог

Проект загружается и запускает главную сцену в Godot 4.7.2 headless. Smoke-тест,
soak-тест, отдельная проверка синтаксиса всех GDScript-файлов и файловый цикл
сохранения/загрузки прошли успешно. Подтверждённых ошибок игровой логики во время
аудита не обнаружено, поэтому игровые скрипты не изменялись.

Исправлены только явные расхождения README с текущим проектом: клавиша запуска,
описание вычисляемых параметров, доступные вкладки навыков, фактическое состояние
контрольных якорей и использование нестандартного пути к Godot.

## Найденные проблемы и исправления

### 1. README указывал неверную клавишу запуска проекта

`Run Project` был сопоставлен с `F6`. В Godot `F5` запускает проект, а `F6` — только
текущую открытую сцену. Инструкция исправлена.

### 2. README содержал устаревшее фиксированное число производных параметров

Интерфейс уже показывает больше параметров, чем заявленные восемь: в том числе
регенерацию маны, регенерацию тела, дальний урон и обзор. Формулировка заменена на
«набор вычисляемых боевых параметров», без изменения баланса или расчётов.

### 3. README не упоминал вкладку навыков ревенанта

В коде и smoke-тесте присутствует вкладка ревенанта с навыком «Острое зрение».
Список доступных вкладок в README обновлён.

### 4. README переоценивал готовность контрольных якорей

`checkpoint_floor` обновляется каждые пять этажей и сохраняется, но пока не участвует
в выборе старта, возрождении или другой игровой механике. README теперь прямо сообщает,
что отдельный эффект якорей в текущем вертикальном срезе ещё не реализован. Механика не
добавлялась, чтобы не менять задуманный геймплей.

### 5. Документация сборки предполагала конкретный локальный путь Godot

`tools/build_windows.ps1` по умолчанию ищет Godot 4.7.2 внутри игнорируемого каталога
`.tools`. README дополнен примером параметра `-GodotPath`, чтобы установленный в другом
месте редактор можно было указать явно.

### 6. Диагностические сообщения headless-среды

При исходных запусках Godot не мог создать журнал в `user://logs`, потому что среда
аудита запрещает запись в пользовательский каталог Windows. В финальных командах журнал
направлен в игнорируемую папку `.tmp`, после чего сообщения о журнале исчезли.

Сообщение `Failed to read the root certificate store` остаётся при любом headless-запуске
в этой изолированной среде, возникает до выполнения игровых тестов и не влияет на их код
завершения. Сетевых функций у текущего прототипа нет; изменение проекта ради обхода
ограничения среды не выполнялось.

## Оставшиеся риски

1. **Нет истории Git.** Все файлы остаются неотслеживаемыми, поэтому Git пока не даёт
   отката, сравнения версий и защиты от случайной потери. Коммит не создавался согласно
   условиям аудита.
2. **Экспорт не проверялся.** Web- и Windows-пресеты читаются, но сборки не создавались.
   Наличие и совпадение версий export templates остаётся проверить отдельно.
3. **Headless не заменяет визуальную проверку.** Полноэкранный режим, реальный геймпад,
   сенсорный ввод и масштабирование на физических мобильных экранах этим аудитом не
   подтверждены.
4. **Сохранение не атомарно.** `Persistence.save_game()` пишет сразу в основной JSON;
   сбой питания или диска во время записи способен оставить повреждённый файл. Главный
   экран также пока не сообщает игроку об ошибке записи.
5. **Шлюз магазина не завершает жизненный цикл.** `StoreGateway.shutdown()` объявлен,
   но пока не вызывается. Для пустого standalone-адаптера это безопасно, однако будущим
   SDK Steam/VK Play понадобится явное завершение.
6. **Крупный UI-контроллер.** `scripts/main.gd` содержит около 3,5 тысяч строк и совмещает
   UI, ввод, бой, видимость и отрисовку. Тесты покрывают текущий срез, но стоимость будущих
   изменений и риск побочных эффектов будут расти.
7. **Генерируемые превью находятся внутри проекта.** Godot сканирует `builds/previews`
   при редакторском импорте, хотя `builds/` игнорируется Git и исключён из экспорта.
   Это не влияет на игру, но увеличивает время импорта по мере накопления превью.
8. **Нет автоматической CI-проверки.** Smoke и soak запускаются только вручную.

## Точные команды повторной проверки

Выполнять из корня проекта в PowerShell:

```powershell
$GodotExe = ".\.tools\godot-4.7.2\Godot_v4.7.2-stable_win64_console.exe"

& $GodotExe --version

& $GodotExe --headless --log-file .tmp/verification-smoke.log `
  --path . --script res://tests/smoke_test.gd

& $GodotExe --headless --log-file .tmp/verification-soak.log `
  --path . --script res://tests/soak_test.gd

& $GodotExe --headless --log-file .tmp/verification-main-scene.log `
  --path . --scene res://scenes/main.tscn --quit-after 10
```

Проверка синтаксиса каждого GDScript-файла:

```powershell
$GodotExe = Resolve-Path ".\.tools\godot-4.7.2\Godot_v4.7.2-stable_win64_console.exe"
$ProjectRoot = (Get-Location).Path

Get-ChildItem -LiteralPath scripts,tests -Recurse -File -Filter "*.gd" |
  Sort-Object FullName |
  ForEach-Object {
    $Relative = $_.FullName.Substring($ProjectRoot.Length + 1).Replace("\", "/")
    & $GodotExe --headless --log-file .tmp/check-only.log `
      --path . --script "res://$Relative" --check-only
    if ($LASTEXITCODE -ne 0) {
      throw "GDScript check failed: $Relative"
    }
  }
```

Проверка состояния Git без изменения рабочего дерева:

```powershell
git status --short --branch
git diff --check
git diff --cached --check
```
